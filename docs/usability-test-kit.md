# 역할극 사용성 테스트 키트

퇴사자·후임·팀장 역할을 나눠 맡은 참여자가 처음 보는 화면으로 인수인계 한 바퀴를 직접 돌려 보는 60분 테스트다. 진행자가 이 문서 하나로 준비부터 기록까지 할 수 있게 썼다. 입력 문장은 모두 [시연 시나리오](demo-scenario.md)의 것을 쓴다.

## 목적과 원칙

목적: 설명 없이 화면만 보고 각 역할이 자기 일을 끝낼 수 있는지, 어디서 막히는지 찾는다. 특히 다음 세 가지를 본다.
- 후임이 넘긴 질문이 퇴사자에게 갔다가 답이 돌아오는 흐름을 이해하는가
- 팀장이 "무엇이 아직 안 넘어왔는지"를 탭 3개(빈 곳 보기·질문 남기기·자료와 문서)에서 찾는가
- 퇴사자가 "내 답을 누가 볼 수 있는지"를 화면에서 알아내는가

원칙:
- 참여자 동의를 먼저 받는다. 시작 전에 무엇을 기록하는지(진행자의 손 메모와 사후 질문지 답) 말하고, 원하면 언제든 그만둘 수 있다고 알린다. 동의하지 않으면 진행하지 않는다.
- 클릭 추적·화면 녹화·실명 기록을 하지 않는다. 관찰은 진행자가 손으로 적고, 참여자는 "참여자 A·B·C" 로만 적는다.
- 실제 회사 정보 대신 데모 시나리오 데이터만 쓴다. 참여자가 자기 회사 업무를 입력하려 하면 멈추고 시나리오 문장으로 바꾼다.
- 테스트하는 것은 화면이지 사람이 아니다. 막힌 지점은 화면의 문제로 적는다.
- 진행자는 과제 중에 답을 알려 주지 않는다. 3분 넘게 막히면 "막힘"으로 적고 다음 과제로 넘어간다.

## 준비물

- 노트북 1대(진행자용, 서버를 띄운다). [uv](https://docs.astral.sh/uv/) 와 Node.js 24 가 있고 `uv sync` 를 마친 상태.
- 실행 환경 둘 중 하나:
  - 로컬 `make try` (권장): 인증을 켠 실제 흐름. 퇴사자 1명을 등록하고 관리자·퇴사자·후임·팀장 초대 링크 4개를 출력한 뒤 역할마다 쿠키가 분리된 창 4개를 연다. 처음이면 `uv run playwright install chromium` 을 먼저 실행한다. 실행마다 새 임시 데이터 폴더를 쓰고 종료하면 지운다.
  - 공개 데모 `/demo` (`make demo` 또는 배포된 주소): 1~10단계가 미리 채워진 세 화면이 한 페이지에 나란히 뜬다. 참여자가 각자 자리에 앉기 어려울 때만 쓴다. 이 경우 퇴사자 과제 1은 이미 끝난 상태라 세션 2부터 한다.
- 참여자 화면: `make try` 의 창을 참여자마다 하나씩 나눈다. 링크를 다른 기기에서 열려면 역할마다 다른 브라우저(또는 프로필)를 쓴다.
- 인쇄물: 역할 카드 3장(아래), 관찰 체크리스트 1장, 사후 질문지 3장, 결과 기록 양식 1장.
- 타이머, 필기구.

## 참여자와 역할 카드

인원 4명: 진행자 1명(관리자 역할 겸함) + 퇴사자·후임·팀장 각 1명. 참여자 이름은 적지 않는다.

| 기록 이름 | 역할 | 화면 |
|-----------|------|------|
| 진행자 | 관리자 | 관리 화면 `/admin` |
| 참여자 A | 퇴사자 | `/` |
| 참여자 B | 후임 | `/chat` |
| 참여자 C | 팀장 | `/report` |

### 진행자 카드 (관리자)
1. 관리 화면에서 등록된 퇴사자 목록을 확인한다. 성공: 별칭 하나가 보이고 퇴사자·후임·팀장 링크 버튼을 찾는다.
2. 연습용 퇴사자를 별칭으로 하나 더 등록한다(실명·이메일 금지). 성공: 목록에 새 별칭이 생긴다.
3. 새 퇴사자의 후임 링크를 만들어 복사한다. 성공: 링크가 복사되고, 같은 브라우저에서 열면 관리자 로그인이 바뀐다는 안내를 읽는다.

### 참여자 A 카드 (퇴사자)
당신은 다음 달 퇴사하는 백엔드 개발자다. 매일 15분, 화면이 묻는 질문에 답한다.
1. 세션을 시작하고 첫 질문이 어디서 왔는지 말한다. 성공: 질문 위 출처 표시(예: `팀장이 우선 지정한 질문`)를 읽고 "팀장이 넣은 질문"이라고 말한다.
2. 카드에 적힌 답 문장(시나리오 단계 8·9)을 보내고, 이어 나오는 꼬리 질문에도 답한다. 성공: 꼬리 질문을 알아보고 `오늘 쌓인 것` 숫자가 늘어난 것을 확인한다.
3. 세션을 마치고 요약을 읽는다. 성공: `오늘은 여기까지` 요약에서 오늘 남긴 내용을 찾아 말한다.
4. "?" 를 하나 열어 내 답을 누가 볼 수 있는지 알아낸다. 성공: 팀장은 본인이 남긴 질문의 답만 본다는 것을 화면 문구로 설명한다.
5. (진행자 신호 뒤) 세션을 다시 시작해 후임이 넘긴 질문에 시나리오 단계 17 문장으로 답하고 세션을 마친다. 성공: 출처 `후임이 물어본 질문` 을 확인하고 세션을 끝낸다.

### 참여자 B 카드 (후임)
당신은 이번 주에 업무를 넘겨받는다. 문서 대신 기록에 질문한다.
1. "결제 대행사 장애가 나면 무엇을 먼저 확인하나요?" 를 묻고 근거를 찾는다. 성공: 근거 상자의 세션 번호를 가리키고, 전화번호가 가려져 있음을 알아챈다.
2. "캐시 서버를 재시작해야 할 때는 어떻게 하나요?" 를 묻는다. 성공: 기록에 없다는 답과 "퇴사자 질문 목록에 올렸다"는 안내를 읽고, 넘긴 질문 탭에서 그 질문을 찾는다.
3. "금요일 배포 금지" 의 이유를 이건 왜 이렇게? 탭에서 묻는다. 성공: 이유가 기록에 없다는 것과 관련 위험 문장을 구분해 말한다.
4. (퇴사자 과제 5 뒤) 넘긴 질문 탭에서 캐시 질문의 대화를 연다. 성공: 퇴사자 답을 대화 화면에서 읽고 "목록으로" 돌아온다.

### 참여자 C 카드 (팀장)
당신은 퇴사자의 팀장이다. 퇴사 전에 무엇이 아직 안 넘어왔는지 확인한다.
1. 자료와 문서 탭에서 모의 업무 자료를 불러오고 자료로 질문을 만든다. 성공: 상태 줄에 불러온 건수·큐에 넣은 질문 수가 뜬다.
2. 질문 남기기 탭에서 "결제 대행사 장애가 나면 가장 먼저 무엇을 확인하나요?" 를 꼭 남겨 달라고 할 질문으로 넣는다. 성공: 다음 세션에 물을 질문 목록에 `팀장 우선` 으로 보인다.
3. 빈 곳 보기 탭에서 가장 비어 있는 축과 빈 구멍 하나를 찾는다. 성공: 축 이름과 빈 구멍 주제 하나를 말한다.
4. 자료와 문서 탭에서 운영 런북을 만든다. 성공: `운영 런북` 상자를 열어 본문을 읽는다.
5. 퇴사자의 다른 답을 볼 수 있는지 화면에서 확인한다. 성공: 다른 사람의 답변 내용은 보이지 않고 내가 남긴 질문의 답만 열린다는 안내를 찾는다.

## 진행 순서

| 시간 | 단계 | 진행자가 할 일 | 참여자 |
|------|------|---------------|--------|
| 0–5분 | 동의와 안내 | 목적·기록 범위·중단 가능을 말하고 동의를 받는다. 이름 대신 참여자 A·B·C 로 부른다 | 동의 |
| 5–10분 | 준비 | `make try` 실행, 창을 역할별로 나눠 주고 역할 카드를 건넨다. 진행자 카드 1~3 을 한다 | 카드 읽기 |
| 10–20분 | 팀장 1·2 | 팀장 과제 1·2 를 관찰한다 | C 진행, A·B 대기 |
| 20–30분 | 퇴사자 1~4 | 퇴사자 과제 1~4 를 관찰한다 | A 진행 |
| 30–40분 | 후임 1~3 | 후임 과제 1~3 을 관찰한다 | B 진행 |
| 40–47분 | 팀장 3~5 | 팀장 창을 새로 고치게 하고 과제 3~5 를 관찰한다 | C 진행 |
| 47–52분 | 루프 닫기 | 퇴사자 과제 5, 이어서 후임 과제 4 를 관찰한다 | A → B |
| 52–58분 | 사후 질문지 | 질문지를 나눠 주고 열린 질문은 말로 듣고 받아 적는다 | 작성 |
| 58–60분 | 마무리 | 서버를 끄고(Ctrl+C) 임시 데이터가 지워졌는지 확인한다. 감사 인사 | - |

## 관찰 체크리스트

과제마다 진행자가 본 대로 체크한다. 체크하지 못한 항목은 결과 기록 양식의 "막힌 지점"에 이유를 적는다.

- [ ] 진행자: 관리 화면에서 퇴사자 등록과 링크 복사를 설명 없이 했다
- [ ] 팀장: 탭 3개 중 어디서 시작할지 30초 안에 골랐다
- [ ] 팀장: 우선 질문이 큐에 `팀장 우선` 으로 들어간 것을 스스로 확인했다
- [ ] 팀장: 빈 구멍을 찾으려고 "?" 도움말을 열었다 (열었다면 도움이 됐는지 메모)
- [ ] 팀장: 다른 사람의 답 원문을 볼 수 없다는 것을 화면 문구로 알아냈다
- [ ] 퇴사자: 질문 출처 표시를 읽고 누가 넣은 질문인지 말했다
- [ ] 퇴사자: 꼬리 질문을 새 질문과 구분했다
- [ ] 퇴사자: 남은 시간 표시를 보고 세션을 언제 마칠지 판단했다
- [ ] 퇴사자: 세션 마치기 버튼을 헤매지 않고 찾았다
- [ ] 후임: 답의 근거 상자를 읽었다
- [ ] 후임: 기록에 없다는 답을 오류로 오해하지 않았다
- [ ] 후임: 넘긴 질문 탭을 스스로 찾았다
- [ ] 후임: 퇴사자 답이 온 뒤 대화 화면을 열고 목록으로 돌아왔다
- [ ] 누구든: 3분 넘게 막힌 과제가 있었다 (있으면 과제 번호를 적는다)
- [ ] 누구든: 화면 용어를 다른 말로 바꿔 불렀다 (그 말을 그대로 적는다)

## 사후 질문지

1~5점: 1 전혀 아니다 · 2 아니다 · 3 보통 · 4 그렇다 · 5 매우 그렇다.

| # | 문항 | 1 | 2 | 3 | 4 | 5 |
|---|------|---|---|---|---|---|
| 1 | 내 역할에서 무엇을 먼저 해야 할지 화면만 보고 알 수 있었다 | ○ | ○ | ○ | ○ | ○ |
| 2 | 버튼과 탭 이름이 무엇을 하는지 바로 이해됐다 | ○ | ○ | ○ | ○ | ○ |
| 3 | "?" 도움말이 막힌 곳을 푸는 데 도움이 됐다 | ○ | ○ | ○ | ○ | ○ |
| 4 | 내가 입력한 내용을 누가 볼 수 있는지 알 수 있었다 | ○ | ○ | ○ | ○ | ○ |
| 5 | 질문이 퇴사자에게 갔다가 답이 돌아오는 흐름이 이해됐다 | ○ | ○ | ○ | ○ | ○ |
| 6 | 이 화면이 나를 평가하거나 감시한다고 느끼지 않았다 | ○ | ○ | ○ | ○ | ○ |
| 7 | 실제 인수인계가 생기면 이 방식을 다시 쓰고 싶다 | ○ | ○ | ○ | ○ | ○ |

열린 질문:
1. 가장 오래 막혔던 곳은 어디였고, 그때 무엇을 기대했나요?
2. 이 화면에서 빼도 되는 것과 꼭 있어야 하는 것을 하나씩 말해 주세요.
3. 내 역할로 일하면서 불편하거나 불안했던 순간이 있었나요?
